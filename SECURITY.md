# Security Policy

## Reporting a vulnerability

Please do not publish vulnerability details in a public issue or pull request.
If private vulnerability reporting is enabled for this repository, use the
GitHub Security tab to submit a private report. Otherwise, contact the
repository owner through the GitHub profile linked from this repository and
ask for a private reporting channel before sharing sensitive details.

Include the affected path or component, impact, and steps to reproduce when it
is safe to do so. Do not include credentials, private user data, or unrelated
secrets in a report.

## Scope

Reports may cover KirzKit's setup and validation scripts, instruction and
workflow files, packaged agent/skill content, or repository configuration.
Third-party or mirrored content may have its own upstream security process;
please identify the affected source when known.

KirzKit does not currently publish supported-version guarantees or a response
time commitment. Reports will be reviewed as maintainer capacity allows.
